# bone-aimedia-services 实施计划

状态：实施路线图。v0.1.0 正在交付 P1 配置、目录检查与三个只读工具；生成任务、下载和执行能力仍未实现。实际可用范围以根目录 README 和运行工具为准。

## 1. 目标与职责

将媒体服务做成独立的 PI-Desktop 插件，支持三种入口：

1. Agent 直接对话：不创建影视作品，也能按授权生成图片、配音或视频并交付文件。
2. 影视工厂：Agent 读取角色／镜头要求与版本，调用媒体服务，随后登记候选、检查并采用。
3. 其他项目／插件：首版通过 Agent 使用相同工具；直接插件间调用在宿主提供受控接口后再接。

| 所有者 | 负责 | 不负责 |
|---|---|---|
| Bone AI 媒体服务 | 服务配置、凭据引用、操作能力、任务状态、生成适配器、结果下载与导出 | 剧本、分镜、作品定稿、自动艺术评分 |
| Bone 影视工厂 | 剧本／节拍／资产／镜头、素材登记采用、剪辑、证据评审与修订 | 供应商密钥、服务配置、直接调用生成 API |
| Agent | 理解需求、发现工具、准备提示词、按授权执行、检查实际素材、报告证据与缺口 | 假装看过视频或听过音频、猜测任务完成、默认重试收费任务 |
| 宿主 | 权限、可信凭据存储、受控网络和进程能力、工具注册与发现 | 以插件自报状态认证艺术质量 |

已有影视作品不迁移到新插件。新插件安装与否均不影响影视工厂导入已有素材。

## 2. 已核实的基础与缺口

依据当前 PI-Desktop SDK 和 DutyDeck 源码调查：

- 插件可注册 Agent 工具；可通过受权限控制的 `pi.net.fetch` 发 HTTP 请求。
- `pi.net.fetch` 当前只返回 `bodyText`，没有通用二进制流下载接口。视频等大文件
  下载不能把文本响应当原始字节使用，也不能绕开宿主直接联网。
- 普通插件设置以 JSON 保存，`secret: true` 被明确拒绝。现有媒体配置原型的
  密钥仅在进程内存，不能将其宣传为持久化安全存储。
- SDK 没有通用 CLI 进程执行接口、插件列表接口或跨插件工具调用接口。
- SDK 有消息总线，但收到／收不到一个插件消息都不等于完成安装状态鉴定；
  总线也不能自动成为带用户授权、取消和请求隔离的 RPC。
- 已有配置原型支持即梦、OpenAI 图片兼容、MiniMax、小米、ComfyUI、LibTV。
  保存配置和只读探测不等于生成执行器已实现。
- DutyDeck 的即梦图片执行链存在，但其统一即梦视频适配器并未接通；不能因为
  配置中有 Seedance 名称就标为支持视频。LibTV 为独立 MCP/OAuth 接入。

### P0 必须做出的工程决策

| 缺口 | 优先方案 | 暂时可行的边界 |
|---|---|---|
| 安全持久化凭据 | 宿主提供插件命名空间隔离的密钥引用及授权调用能力 | API Key 仅进程内存，明确重载失效；禁止明文落盘 |
| 二进制结果下载／交付 | 宿主提供受控下载到私有存储或工作区的 API，具备大小、路径、重定向与取消检查 | 由实际可用且获授权的 Agent 下载／文件工具完成，不宣称插件独立自动交付 |
| 即梦 CLI | 宿主提供限定命令、参数数组、超时与取消的进程服务，或独立受控执行扩展 | Agent 通过现有 CLI 技能执行；插件只记录经核验的任务，不伪造原生执行状态 |
| 插件安装检测 | 宿主提供不泄露敏感信息的插件清单／能力发现接口 | Agent 发现工具并读取能力；缺失仅报告当前不可用或未暴露 |
| 插件直接协作 | 先完成 Agent 工具契约；后续再设计有调用方身份和权限的宿主接口 | 不共享私有配置文件、不偷读凭据、不以裸消息总线绕过审批 |

如需修改宿主安全边界，另立宿主任务、提出方案与兼容影响，并按宿主要求记录 ADR。
本轮仅规划，不修改宿主或其权限登记。

## 3. 首版范围

### 配置与能力页

按用户指定，样式与交互参考 DutyDeck 媒体配置，采用“生成模型／音频生成／LibTV／
服务链接／本地工作流”一级分区，以及“列表页 → 独立添加／编辑页”结构。
编辑页分为基本信息、已启用模型和可用模型，常规操作不要求手写模型列表文本。
具体布局、视觉参数、交互及验收见[界面设计规范](ui-design.zh-CN.md)。配置读取不自动访问远端。

配置采用版本化全量保存和乐观锁。密钥只使用安全引用或明确的临时内存输入，不出现在
Agent 返回值、日志、错误、导出配置、工作流 JSON 或影视作品中。切换供应商／地址时
不得自动复用原密钥。复制配置不复制凭据。

### 操作能力按实际适配器声明

| 服务 | 第一阶段目标 | 后续目标／前置条件 |
|---|---|---|
| OpenAI 图片兼容 | 文生图，再做参考图编辑；模型目录与真实图片端点分别验证 | 需文件字节读取、multipart 上传和结果交付能力 |
| 小米 MiMo | 文本转语音，明确模型、voice、format、精确朗读正文与表演指令 | 不默认包含音色克隆／设计；需按当前官方协议复核 |
| 即梦 | 外部 CLI 的能力与登录说明、真实任务 ID 查询协作 | 受控执行能力确定后，依次接文生图、图生图、单帧视频、首尾帧视频 |
| MiniMax | 先语音，再图片和视频 | 复核音频编码、视频 task/file_id/download 链，不直接照抄旧解析器 |
| ComfyUI | 连接与节点发现、API 工作流和绑定校验 | 后接上传、提交、历史查询、输出下载；仅取消本插件任务，不调用全局 interrupt |
| LibTV | 明确使用宿主 MCP/OAuth 的路径 | 工具能力来自授权后的真实服务，不预设不存在的固定接口 |

不要第一版同时铺开全部模型。顺序是：一个图片服务与一个配音服务跑通，再完成一个
可恢复的视频服务，随后扩大 ComfyUI 和其他供应商覆盖。仅配置的能力必须显示为
`configuration-only`，不能与 `native` 或 `agent-mediated` 执行混为一谈。

### 任务中心

统一查看任务、费用状态、远端 ID、结果及失败原因。禁止页面读取触发生成。
任务详情显示提交时的提示词和参数快照、配置修订号、输入引用哈希、目标信息、结果列表。
私有提示词不写公开发布文档；供应商原始错误和签名下载 URL 必须脱敏。

## 4. 对 Agent 的接口设计

具体字段草案见 [接口草案](api-contract-draft.md)。建议以七个工具形成最小闭环：

1. `get_capabilities`：无网络、无秘密，返回契约版本、操作支持范围、限制和阻塞项。
2. `list_profiles`：列出可供本次任务选择的服务与模型，不返回密钥。
3. `prepare_generation`：校验并保存不可变请求草案，不联系供应商、不收费。
4. `submit_generation`：在有效授权与草案版本下提交一次，先持久化本地任务再外发。
5. `get_generation`：读状态；明确请求刷新时才查询已有远端任务，不重复提交。
6. `cancel_generation`：说明是否仅停止本地等待、取消队列或远端确已取消。
7. `export_result`：将指定结果交付到获授权的工作区路径，核对 SHA，默认禁止覆盖。

工具名称仅为草案。正式实现和宿主注册成功后才可调用；Agent 始终先发现实际名称和 schema。
导出任务不自动采用到影视工厂，也不写入评审结论。

## 5. 状态机、恢复与费用

主状态：`prepared → submitting → queued/running → succeeded/failed/cancelled`。
额外状态：`unknown` 表示外发后结果不确定；`result-pending` 表示生成已完成但文件尚未
下载并验证。只有真实结果字节保存成功才标为 `succeeded`。

- 使用调用方稳定 `requestKey` 与规范化请求哈希。相同键、相同内容返回同一任务；
  同键不同内容拒绝，不能把用户点击两次解释为两笔生成。
- 在网络请求前写入本地任务与 `submitting` 状态；得到远端 ID 后立即原子保存。
- 重启遇到 `submitting` 且无法确定远端是否收到时进入 `unknown`，不自动重发。
  供应商幂等键可减轻重复，但不能普遍承诺“恰好一次”。
- 远端生成成功、下载失败时保留远端任务，只重试下载，不再次生成。
- 取消不能保证退款。远端无取消接口时清楚报告只停止轮询，后续仍可查询结果。
- 用户授权记录包含数量、范围、供应商／模型、允许的预算与有效期。Agent 声明
  不等于宿主认证同意，宿主审批仍执行。
- 费用区分已报价、估算、实际返回和未知，不编造价格。仅在有可靠定价或额度
  接口时自动校验金额上限，否则明确不支持强制成本上限，并在提交前取得范围授权。
- 提供手动刷新和受控轮询；超时、限流和断网不触发无界自动重试。

## 6. 与影视工厂的协作契约

影视工厂读取镜头后，Agent 带上可选 `consumer` 元数据：插件 ID、作品 ID、资产或
镜头 ID、镜头版本及相关内容哈希。这些值由调用方提供，仅作为来源记录，新插件不
将其当权限证明，也不直接打开其他插件的私有文件。

结果流程：

```text
Agent 读取当前作品与镜头版本
  → 发现媒体工具并核验操作能力
  → 准备请求与输入素材
  → 按授权提交 / 查询同一任务
  → 获取并检查真实结果文件
  → 导出到当前工作区 bone-media/<productionId>/
  → 影视工厂 register_media（保留提交时版本）
  → Agent 依据实际证据 record_review
  → 在授权范围内 adopt_media
```

如果镜头在生成期间变化，不把旧结果伪装成无归属素材来绕过版本检查。报告冲突、保留
任务与文件，按实际变更决定新请求或重新核验。审核通过与采用是独立操作，不能互相冒充。

Agent 直接对话可省略 `consumer`；其他项目使用自己的稳定来源标识，不需要创建影视作品。

## 7. Agent 审查职责

- 图片：必须查看实际图片，核对主体身份、构图、道具、文字、风格与约束。
- 视频：观察完整必需动作和实际采用区间；静帧或抽帧只支持观察过的静态事实，
  不能据此认证运动、接触、表演和全部切点连续性。
- 声音：实际收听才能对听感、清晰度、说话者和音画同步下结论；解码、波形和
  ASR 只能支持对应技术事实。
- 记录素材 ID／SHA、观察方式、时间范围、发现与剩余问题。能力或证据不足时
  用 `not-verified`，明确需要人工检查什么。
- 新插件负责执行与技术元数据，不内置“专业质量分数自动通过”。作品级审查
  继续写入影视工厂；独立对话在交付报告中给出同样的证据范围。
- 审查请求不授权重新生成、付费重试、修改剧本或自动覆盖采用结果。

## 8. 数据与模块划分

拟定私有存储（具体 schemaVersion 在实现时固定）：

```text
profiles.json                 # 非敏感配置与凭据引用
jobs/<jobId>/request.json      # 不可变提交快照
jobs/<jobId>/state.json        # 原子写状态与修订号
results/<sha256>.<extension>   # 实际媒体字节
```

结果保留策略需显式设置，不因删除服务配置就删除已生成文件。配置仍被任务引用时保留
历史快照。读写检查路径、符号链接、文件大小、签名、字节哈希与工作区切换。

实现按职责拆分为配置服务、能力目录、请求验证、任务状态机、存储、供应商适配器、
媒体导入导出、Agent 工具和 UI。不将所有供应商协议堆在入口文件中。

## 9. 从当前原型迁移

迁移参考代码保留在 `../.worktrees/bone-video-workshop-media-providers/`：
`lib/media-provider-*.js`、`views/media-providers.*`、对应测试与说明。
这是本地未提交原型参考，不是新插件已安装的证明，也不应成为发布运行依赖。

迁移时：

1. 先按当前宿主模板用 PluginScaffold 创建独立插件结构，审查许可证与来源。
2. 迁移纯配置验证、界面和测试，替换插件 ID、命名空间、资源和权限声明。
3. 配置导入由用户明确导出／选择文件触发，经宿主读取权限导入非敏感数据。
   不直接读取影视工厂私有目录，不自动删旧文件，不复制旧凭据。
4. 重新校验模型、供应商和默认项；重建独立配置 ID，旧 ID 只保留为来源映射。
5. 单独配置密钥；不假定旧插件进程中的临时密钥可迁移。
6. 验证新插件单独工作，再验证 Agent 联动影视工厂；旧作品和已有素材保持不变。

## 10. 分阶段交付与验收

| 阶段 | 交付 | 必须通过的验收 |
|---|---|---|
| P0 契约与宿主能力核对 | 确定凭据、字节下载、CLI、发现机制和权限方案 | 每项能力有实际接口或明确 fallback；未实现项显示阻塞，不能假通过 |
| P1 独立配置插件 | 分类配置页、版本化存储、无秘密能力查询、明确状态 | 无作品也能用；配置不收费不联网；并发冲突、重载、密钥生命周期、URL/日志脱敏通过 |
| P2 图片与配音 | 一个真实图片服务、一个真实 TTS 服务，统一任务与文件交付 | 幂等键、错误、撤销与超时、真实输入输出、候选不自动采用；小样数量和预算明确 |
| P3 异步视频 | 一个视频服务完整提交／查询／恢复／下载 | 中断恢复不重复付费；生成成功下载失败仅重试下载；版本冲突不覆盖镜头 |
| P4 Agent 联动验收 | 直接对话与影视工厂各一条完整路径 | 生成、技术核验、真实观察、候选登记、明确采用可追踪；没有媒体工具时可降级 |
| P5 更多适配与交互 | ComfyUI 执行、更多服务、可选宿主直连接口 | 每种操作独立声明与测试，新增供应商不改作品 schema |

每阶段先跑纯状态／协议测试，再跑注入式适配器测试和隔离 UI 用户路径。真实服务验收
使用独立测试账号或已授权账号、明确预算和可追踪任务；禁止拿正式作品做破坏性试验。

### 停止条件

- 未解决安全凭据或结果下载边界：可以交付 P1，但不能宣称原生自动生成闭环完成。
- 返回任务状态不确定：保留 `unknown`，不盲重试。
- 没有实际视听能力：保留审查缺口，不以工具成功替代。
- 未获商用所需第三方权利：不承诺商业替代许可覆盖全部代码或素材。

## 11. 首版范围

v0.1.0 建立独立配置插件和只读能力接口，不提交生成任务、不读取旧凭据、不修改宿主 SDK，
也不创建远端仓库或公开发布。后续 P2–P5 仍按上述前置条件和验收标准推进。
